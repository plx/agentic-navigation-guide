| Command  | What it does                                                  |
| -------- | ------------------------------------------------------------- |
| `init`   | Generate a guide in a new file.                               |
| `dump`   | Print a generated guide to stdout.                            |
| `check`  | Validate guide syntax.                                        |
| `verify` | Validate syntax and compare listed paths with the filesystem. |

Use `agentic-navigation-guide <command> --help` for all options.

## `init`

Create a starting guide from the current directory tree:

```sh
agentic-navigation-guide init --output AGENTIC_NAVIGATION_GUIDE.md
```

`--output` is required. The destination must not already exist, and its parent
directory must exist. Edit the generated guide to select useful paths and add
comments.

## `dump`

Preview a generated guide without writing a file:

```sh
agentic-navigation-guide dump --depth 2 --exclude target --exclude .git
```

To write it to a new file:

```sh
agentic-navigation-guide dump --output tree.md
```

Like `init`, `dump --output` refuses to overwrite an existing destination.

## `check`

Validate syntax without comparing listed paths to the filesystem:

```sh
agentic-navigation-guide check
agentic-navigation-guide check --guide path/to/guide.md
```

The default guide is `AGENTIC_NAVIGATION_GUIDE.md` in the current directory.

## `verify`

Check syntax, path names, file and directory types, and placeholders:

```sh
agentic-navigation-guide verify
```

By default, the root is the current directory and the guide is
`AGENTIC_NAVIGATION_GUIDE.md` beneath it. You can select both explicitly:

```sh
agentic-navigation-guide verify --guide path/to/guide.md --root path/to/project
```

To discover guides beneath a root and verify each relative to its own parent
directory:

```sh
agentic-navigation-guide verify --recursive
```

A recursive run fails if no guides are found. Use `--allow-empty` only when an
empty search is an acceptable result; it does not suppress other failures.

## Ignored guides

A guide marked `ignore=true` is reported as ignored and succeeds by default.
Its body is not checked. To make an ignored guide fail the command:

```sh
agentic-navigation-guide check --deny-ignored
agentic-navigation-guide verify --recursive --deny-ignored
```

This policy is separate from output modes such as `--github-actions-check`.
See [CI and hooks](../ci/) for automation examples.

## Configuration and exit status

Command-line options take precedence over environment variables, which take
precedence over built-in defaults. See the
[configuration reference](https://github.com/plx/agentic-navigation-guide/blob/main/docs/v0.2-contract.md#command-line-and-environment-configuration)
for the five supported environment settings.

In the default mode, success exits `0`, a failed check exits `1`, and an invalid
invocation exits `2`. An allowed ignored guide also exits `0`. Post-tool-use
mode uses `2` for verification failures. See the
[output reference](https://github.com/plx/agentic-navigation-guide/blob/main/docs/v0.2-contract.md#stable-streams-and-exit-statuses)
for every mode and outcome.

## Filesystem limits

Guides describe regular files and directories. Guide files and listed entries
cannot be symbolic links; recursive discovery does not traverse descendant
links. The checks assume a stable filesystem while the command runs.

For exact path, platform, and file-writing guarantees, see the
[filesystem reference](https://github.com/plx/agentic-navigation-guide/blob/main/docs/v0.2-contract.md#filesystem-trust-and-containment).
